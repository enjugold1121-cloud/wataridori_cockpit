# 渡り鳥の操縦席（試作）

画面を一目見れば「今日はこれをすればいい」「これは今やらなくていい」「生活のことも忘れていない」が分かる、iPad向けの小さな操縦席。

ビルド不要の静的Webアプリ。GitHub Pagesで公開している。

公開URL：https://enjugold1121-cloud.github.io/wataridori_cockpit/

## 公開について

- 公開しているのはプログラムとサンプルの文面だけ。リポジトリも公開設定なので、誰でも読める
- 入力したタスクはサーバーへ送らず、開いているブラウザの中だけに保存する
- 実在の案件名や個人情報、認証情報をコードやサンプルに書かない

## 更新

`main` ブランチへ push すると、数分でGitHub Pagesへ反映される。

PCだけで確認するときは `start.bat` をダブルクリックする（Python 3 が必要）。`http://localhost:8765` で開き、公開版とはデータが別になる。

## iPadの設定

1. Safariで公開URLを開く
2. 共有 → 「ホーム画面に追加」で全画面表示になる
3. 設定 → 画面表示と明るさ → 自動ロック → 「なし」（アプリ側では画面ロックを解除できない）
4. 画面の縦向きロックを外し、横向きで使う

### データの保存について

- データはまずブラウザごとに保存される。PCとiPadで揃えるには、設定の「PCとiPadで付箋を共有」を使う
- ホーム画面のアイコンとSafariのタブでも保存先が別になる。最初からホーム画面のアイコンで使う
- ブラウザのWebサイトデータを消すと、タスクも消える
- 最初の読み込みにはインターネット接続が必要

### 保存データ（localStorage `wb.v1.*`）

| キー | 内容 | 日付変更時 |
|---|---|---|
| `holds` | 保留タスク | そのまま残る |
| `work` | 仕事タスク（日付 → ブロックID → 付箋） | その日に残る。翌日へ移動しない |
| `workRepeats` | くり返し付箋の雛形（予定の名前に紐づく） | 残る。同じ名前の予定がある日に1枚ずつ貼る |
| `repeatLog` | くり返し付箋を貼り済みの日（外した日も含む） | 残る。外した日に貼り直さないために使う |
| `lifeTemplate` | 生活の雛形（時間帯ごと） | そのまま残る |
| `lifeLog` | 生活の完了記録（日付別） | 新しい日は空から始まる |
| `history` | 完了履歴 | 残る |
| `settings` / `timer` | 設定 / タイマー | 残る |

### 1日の区切り

午前の開始時刻（初期値 05:00）で日付が切り替わる。深夜1時はまだ前日の夜として扱い、時間割には「◯月◯日の続き」と表示する。

## Googleカレンダー連携

Apps Script の Web アプリ（`gas/calendar-relay.js`）が予定を読み取り専用で取得し、操縦席はそこから受け取る。

- 中継が返すのは予定のID・名前・開始と終了の時刻だけ。説明・場所・参加者は返さない
- 鍵が一致しない呼び出しには何も返さない。鍵はスクリプトプロパティ `ACCESS_KEY` と、各端末の設定にだけ置く（このリポジトリには置かない）
- 読む予定表はスクリプトプロパティ `CALENDAR_IDS`（カンマ区切り）。未設定ならメインのカレンダー
- 付箋は予定の `event.id`（繰り返し予定は回ごとに別のID）で紐づくので、時刻が変わっても同じ予定に付いたまま
- 予定が消えた・別の日へ動いた付箋は「予定が見つからない付箋」の枠に残る
- 予定は10分ごとに取り直す。取得に失敗したときは、前回取得した予定を表示する
- 終日の予定は今は表示しない。日をまたぐ予定は、その日の24:00までとして扱う

### つなぎ方

1. `gas/` を Apps Script にアップロードする（`clasp push`。`.clasp.json` はリポジトリに含めない）
2. エディタで `setupKey` を実行し、カレンダーの閲覧を許可する。実行ログに鍵が出る
3. 「デプロイ」→「新しいデプロイ」→ 種類は「ウェブアプリ」、実行ユーザーは「自分」、アクセスは「全員」でデプロイし、URL を控える
4. 操縦席の「設定」→「Googleカレンダー連携」に URL と鍵を入れて「接続する」。端末ごとに行う

鍵を変えたいときは `setupKey` をもう一度実行し、各端末の設定を入れ直す。`checkToday` を実行すると、今日の予定が読めるか（件数と時刻）をログで確かめられる。

## PCとiPadで付箋を共有

同じ中継（`gas/sync-store.js`）を通して、Google ドライブのファイル `wataridori-cockpit-data.json` に保存する。中継が読み書きできるのは、自分で作ったこのファイルだけ（`drive.file` の権限）。`appsscript.json` の Drive（高度なサービス）は、Drive API を有効にするためのもの（無効だとファイルを作るときに 403 になる）。

- 共有するもの：保留・仕事の付箋・くり返し付箋・生活の付箋（雛形と完了記録）・完了履歴。設定とタイマーは端末ごと
- 変更は1.5秒待ってまとめて送り、30秒ごと・画面に戻ったときに新しい分を受け取る。つながらないときは端末に残し、30秒ごとに送り直す
- 単位は「保留」「雛形」などのまとまりと、仕事の付箋・生活の完了記録の1日分。同じ単位を2台がほぼ同時に変えたときは、後から保存したほうが残る（そのときは画面で知らせる）
- 「共有を始める」を最初に押した端末の内容が基準になる。後から始めた端末は確認のうえ共有データに置き換わり、置き換える前の内容は端末に `wb.v1.backup.*` として残る
- 中継のコードを変えたら、「デプロイを管理」で新しい版に更新する（URLは変わらない）。`checkSync` で共有データが読めるか確かめられる
