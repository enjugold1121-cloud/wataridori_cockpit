# 渡り鳥の操縦席（試作）

画面を一目見れば「今日はこれをすればいい」「これは今やらなくていい」「生活のことも忘れていない」が分かる、iPad向けの小さな操縦席。

ビルド不要の静的Webアプリ。GitHub Pagesで公開している。

公開URL：https://enjugold1121-cloud.github.io/wataridori-cockpit/

## 公開について

- 公開しているのはプログラムとサンプルの文面だけ。リポジトリも公開設定なので、誰でも読める
- 入力したタスクはサーバーへ送らず、開いているブラウザの中だけに保存する
- 実在の案件名や個人情報、認証情報をコードやサンプルに書かない

## 更新

`main` ブランチへ push すると、数分でGitHub Pagesへ反映される。

PCだけで確認するときは `start.bat` をダブルクリックする（Python 3 が必要）。`http://localhost:8765` で開き、公開版とはデータが別になる。

## iPadの設定

1. Safariで公開URLを開く
2. 共有 → 「ホーム画面に追加」で全画面表示になる
3. 設定 → 画面表示と明るさ → 自動ロック → 「なし」（アプリ側では画面ロックを解除できない）
4. 画面の縦向きロックを外し、横向きで使う

### データの保存について

- データはブラウザごとに別々に保存される。PCとiPadの間では同期されない
- ホーム画面のアイコンとSafariのタブでも保存先が別になる。最初からホーム画面のアイコンで使う
- ブラウザのWebサイトデータを消すと、タスクも消える
- 最初の読み込みにはインターネット接続が必要

## 構成

```
index.html              画面の骨組み
styles.css              見た目（色はすべて先頭の変数で管理、ライト/ダーク対応）
js/time.js              日付と時間帯の計算
js/store.js             データと保存（保存先はアダプタで差し替え可能）
js/calendar-provider.js 予定の取得元（現在はサンプル、読み取り専用）
js/app.js               操縦席の画面と操作
js/calendar-view.js     全体カレンダー
vendor/Sortable.min.js  ドラッグ&ドロップ（SortableJS 1.15.6 / MIT）
start.bat               PCでの確認用サーバー
.nojekyll               GitHub Pagesでファイルをそのまま公開する指定
```

### 保存データ（localStorage `wb.v1.*`）

| キー | 内容 | 日付変更時 |
|---|---|---|
| `holds` | 保留タスク | そのまま残る |
| `work` | 仕事タスク（日付 → ブロックID → 付箋） | その日に残る。翌日へ移動しない |
| `lifeTemplate` | 生活の雛形（時間帯ごと） | そのまま残る |
| `lifeLog` | 生活の完了記録（日付別） | 新しい日は空から始まる |
| `history` | 完了履歴 | 残る |
| `settings` / `timer` | 設定 / タイマー | 残る |

### 1日の区切り

午前の開始時刻（初期値 05:00）で日付が切り替わる。深夜1時はまだ前日の夜として扱い、時間割には「◯月◯日の続き」と表示する。

## Googleカレンダー連携（第2段階）

`js/calendar-provider.js` を同じ形の実装に差し替える。画面側の変更は基本的に不要。

```
getEvents(fromKey, toKey) → {'YYYY-MM-DD': [{id, title, start:'09:00', end:'10:00', kind:'work'|'fixed'}]}
```

- `id` に Google の `event.id` を入れる。付箋はこのIDで予定に紐づくので、予定の時刻が変わっても付箋は同じブロックに付いたまま
- スコープは読み取り専用（`calendar.events.readonly`）に限定し、書き込みは行わない。`connected: true` にすると未接続表示が消える
- 認証情報はコードに書かない。リポジトリが公開なので特に注意する
- 接続方式の候補は2つ
  - **Google Identity Services（ブラウザで完結）：** 公開URLがHTTPSなので利用できる
  - **Apps Script Webアプリを中継：** 既存のGAS運用に近く、認証情報をブラウザに置かずに済む
- 第2段階で追加が必要な処理
  - 終日予定と、日をまたぐ予定の表示
  - 予定が消えた・別の日へ動いたときの付箋の扱い（「時間未定」に残して消さない）
  - 取得失敗時は前回の予定を表示する

## 保存先の変更

`js/store.js` の `localStorageAdapter` と同じ形（`load(name)` / `save(name, value)`、非同期可）を実装し、`const adapter = …` を差し替える。
